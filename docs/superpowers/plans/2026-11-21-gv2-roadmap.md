# Gedcom.Vector 2.0.0 Plan Roadmap

Spec: `docs/superpowers/specs/2026-11-21-gedcom-vector-2-0-design.md` (approved 2026-11-21).

The design spans several subsystems, so it is delivered as a sequence of plans, one per phase. Each plan produces working, tested software on branch `feature/v2.0` and is written in detail only once its predecessor has landed, because later plans name types and signatures that earlier plans create. Each plan ends with all tests green, zero warnings, the AOT job green, and a whole-plan code review.

**Benchmarks throughout (user requirement):** a start-point run on unchanged 1.3.2 (.NET 8), the .NET 10 baseline in Plan 1, and a checkpoint row in `docs/benchmarks/history.md` after every task that touches parsing, the model, writing or the context, via `tools/Run-Benchmarks.ps1`. A row over +10% against the baseline is raised in that task's review, not left for Plan 8. Rows record allocated bytes as well as the mean. The export benchmarks are gated against the lower of the .NET 8 start point and the .NET 10 baseline, because the .NET 10 figure carries a background-GC cost caused by the 1.3.2 writer's allocations (`docs/benchmarks/2026-11-22-export-gc-investigation.md`).

**Carried from Plan 1 (parked at its final review, each owned by the plan named):**
- Done in Plan 2 Task 1: the `tools/Run-Benchmarks.ps1` hardening.
- Plan 6 (smoke app move): a distinct exit code for output write failures; a `--config` mode that runs `AddGedcomImport` under AOT and prints the bound value; separate `obj/` for the AOT and JIT publishes in `Compare-AotJit.ps1`; a README note that local Windows AOT needs `vswhere.exe` on PATH; drop the repeated `CultureInfo.InvariantCulture` qualification when porting `ParserBenchmarks`.
- Plan 7: the smoke corpus `README.md` falls under the `binary` gitattributes rule (diffs hidden); narrow the rule to the data files.
- Plan 8: the package Description ("zero external dependencies" is false since 1.3.2); the investigation doc's third table row rounds -6.6% to -6%.

**Carried from Plan 2 (parked at its final review, each owned by the plan named):**
- Benchmarks: this laptop drifts between sessions (CreateTreeContext reads +28% against its reference while the baseline commit measures the same today). Before calling any row over +10% a regression, rerun that benchmark at the baseline commit in the same session.
- Private corpus: `GEDCOM_VECTOR_PRIVATE_CORPUS` is a list of file paths. No private run until the user names the file list (a Plan 2 run read a second private file from a shared folder). Wrap `File.ReadAllBytes` in the private test so an IO error reports `file #N`, not the path.
- Plan 3: a severity table test for every diagnostic code, with `LineWithoutLevelUnplaced` reconsidered as a Warning now that its text is kept; null `tag` rendering `?`; `StructureAssert` untested branches and both tags in its tag-differs message; move `DiagnosticArguments` to `Diagnostics/`; document that line accounting keeps every structure reachable; pin the ANSEL combining mark before a CONT; untested version and codec rows; a shared corpus-path helper; a raw first line `@` plus `2 CONC @x` joins into `@@` and loses an `@`; an unplaced-text placeholder is decoded like a value (`@@x` to `@x`, `@I1@` flagged as a pointer).
- Plan 4: 5.5.1 raw `@@#DJULIAN@` decodes to `@#DJULIAN@` and re-encodes as a real calendar escape.
- Plan 5: the writer must emit tagless placeholder structures (`<level> [xref]`, value as CONC/CONT lines); validate `ValueIsPointer` on non-pointer values.
- Plan 6: expose `MaxDiagnostics` with validation and decide whether the cap may hide Error-level and reader-level diagnostics (`SuppressedCount` is internal); decide diagnostic order (raise order today, not line order); cap total value length with a diagnostic (a value can grow through CONT and level-less appends, bounded today only by `MaxFileSizeBytes`); back off one character when line truncation would split a surrogate pair; the AOT smoke app catches only IO exceptions in `--structures`; tab as a delimiter is still a level-less line.
- Plan 8: Run-Benchmarks clarity items (local `$commit` name, stamp before the run, `-dirty` after appended rows, catch output); ANSEL input copies every all-ASCII value; `BuildPath` allocates after the cap; `ParseGedcomText` uses an unbounded diagnostic bag and parses a whole second record before rejecting; lazy `Children` lists, pooled pointer values and the fold copy (the new reader is 6.7 ms and 8.4 MB against 3.1 ms and 2.7 MB for 1.3.2 on the benchmark).
