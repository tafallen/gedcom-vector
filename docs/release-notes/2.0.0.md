# Gedcom.Vector 2.0.0 release notes (in progress)

Plan 8 completes these notes with the breaking-change table generated from the PublicAPI diff and the migration paths.

## Behaviour changes so far (Plan 1)

- Targets `net10.0` only and depends on Microsoft.Extensions.* 10.0.x. Consumers on earlier runtimes stay on 1.3.x.
- Native AOT and trimming compatible (`IsAotCompatible`). Options binding uses the configuration binding source generator, so no reflection is needed.
- New `AddGedcomImport(IServiceCollection, Action<GedcomImportOptions>)` overload for consumers without a configuration object.
- `AddGedcomImport` null arguments now throw `ArgumentNullException`; 1.3.2 threw `NullReferenceException`. Migration: catch the new type if you caught the old one.
- Options validation stays a plain-code delegate (`.Validate(...)`); the `[OptionsValidator]` generator is not used. No user-visible change.
- UTF-8 GEDCOM 7.0 files no longer get a false "GEDCOM 7.0 requires UTF-8 encoding" error. A 7.0 file whose `CHAR` declares anything other than UTF-8 (including a value the library does not recognise and therefore decodes as UTF-8) still gets it.
- Files starting with a UTF-8 BOM now have the BOM consumed, so the HEAD record is read. SpecVersion detection and the Unparsed and Errors counts can change for such files. Migration: re-check any assertions on those values for BOM files.
- GEDZIP entries now carry a fixed 1980-01-01 00:00 timestamp, so GEDZIP output is byte-for-byte deterministic.
- The import summary log line is emitted through `[LoggerMessage]` with a generated EventId and name; 1.3.2 used EventId 0. Migration: update any log filters keyed on EventId 0.
- `InternalsVisibleTo FAMTree.Api.Tests` removed.
- Known: `GedcomExportWriter` allocates about 3.9x its output and is about 35 to 50% slower than on .NET 8 under background GC. It is fixed by the Plan 5 writer; see [the investigation](../benchmarks/2026-11-22-export-gc-investigation.md).
